UEH-WebSEM User Guide

How to build a model, run PLS-SEM / CB-SEM, and read every result table — illustrated throughout with the built-in TAM sample dataset (n = 250) and real numbers produced by this tool.

1. What is UEH-WebSEM?

UEH-WebSEM is a browser-based structural equation modeling (SEM) tool supporting two estimation approaches on the same visual model:

  • PLS-SEM (Partial Least Squares) — composite-based, robust with non-normal data and smaller samples, supports formative measurement, and is the estimator used for bootstrapping, Q² (blindfolding), and Common Method Bias testing.
  • CB-SEM (Covariance-Based, Maximum Likelihood) — produces classic model-fit indices (CFI, RMSEA, SRMR, …) and exact standard errors, but only supports reflective measurement.

Both estimators run on the exact same structural diagram, so you can build one model and compare how the two methods treat it.

2. Three-step workflow

1

Upload data

CSV or Excel, one column per indicator, one row per respondent (max 5,000 rows). Or click “Use sample data” to load the built-in Technology Acceptance Model (TAM) dataset used throughout this guide.

2

Build the model

Double-click the canvas (or “+ Construct”) to add a construct, assign indicators, then switch to path mode to draw structural arrows between constructs.

3

Run & read results

Choose PLS-SEM or CB-SEM, optionally enable bootstrapping, run the analysis, and read the tables described in this guide — then export to Excel/Word.

3. Building a model

A model is a set of constructs (latent variables) connected by structural paths (arrows). Each construct is measured by one or more indicators — numeric columns from your uploaded data.

Reflective vs. formative measurement

  • Reflective (Mode A) — indicators are interchangeable manifestations of the same underlying construct (e.g. three survey items all measuring “Attitude”). Needs ≥ 2 indicators. This is the only mode CB-SEM supports.
  • Formative (Mode B) — indicators jointly define the construct (e.g. socio-economic status formed by income + education + occupation). PLS-SEM only.

The sample TAM dataset ships with four reflective constructs and five structural paths:

Perceived Ease of Use (PEOU) ──▶ Perceived Usefulness (PU) Perceived Ease of Use (PEOU) ──▶ Attitude (ATT) Perceived Usefulness (PU) ──▶ Attitude (ATT) Perceived Usefulness (PU) ──▶ Behavioral Intention (INT) Attitude (ATT) ──▶ Behavioral Intention (INT)

Notice PEOU has no direct arrow to Intention — its influence only reaches Intention through PU and Attitude. That makes this sample model a ready-made illustration of mediation, which we use for real numbers below.

4. Mediator constructs

A mediator is an endogenous (dependent) construct that sits between a predictor and an outcome, transmitting part or all of the predictor's effect. In the TAM model, Perceived Usefulness and Attitude both act as mediators between PEOU and Behavioral Intention.

You don't need a separate "mediator" construct type — any construct that is simultaneously a target of one path and the source of another is automatically a mediator. UEH-WebSEM detects every such indirect route on its own and reports it in the Total & Indirect Effects table, computed as:

Formula Indirect effect (X → Y) = Σ, over every indirect route from X to Y, of the product of the path coefficients along that route.
Total effect (X → Y) = Direct effect + Indirect effect.

Worked example, with real numbers from the TAM sample

How 0.293 was obtained: PEOU reaches Intention along two routes — PEOU→PU→Intention (0.462 × 0.354 = 0.164) and PEOU→Attitude→Intention (0.206 × 0.359 = 0.074) — plus the three-step route PEOU→PU→Attitude→Intention (0.462 × 0.331 × 0.359 = 0.055). Summing all three gives 0.164 + 0.074 + 0.055 ≈ 0.293, exactly what the table reports. The tool does this arithmetic for you across every construct pair automatically.

Reading the Total & Indirect Effects table in practice

  • Indirect = 0 means the two constructs are connected only by a direct path (no mediator in between) — Total simply equals Direct.
  • Direct = 0, Indirect ≠ 0 (like PEOU → Intention above) signals full mediation: without the mediator(s), the predictor would appear unrelated to the outcome.
  • Both non-zero and the same sign (like PU → Intention) signals complementary mediation: the mediator reinforces the direct effect.
  • Both non-zero with opposite signs would signal competitive mediation (a suppression effect) — none of the sample paths show this, but watch for it in your own models.
Want significance on one specific route? The Total & Indirect Effects table above sums every route between a pair of constructs, so it can't tell you whether any one specific chain is itself statistically significant. §5, Specific Indirect Effects breaks that sum back down into its individual routes, each with its own bootstrap t-statistic, p-value, and confidence interval — computed directly on that route's own a × b (× c …) product, across the same resamples, rather than the informal causal-steps check this guide used to recommend.

5. Specific Indirect Effects

When two constructs are connected by more than one mediated route — as PEOU and Behavioral Intention are in the TAM model, via PU alone, via Attitude alone, and via both together — the Total & Indirect Effects table only shows their sum. Specific Indirect Effects reports each route separately, with its own bootstrap significance test, so you can tell exactly which chain is driving the overall indirect effect.

Running PLS-SEM with bootstrapping (2,000 resamples) on the TAM sample produces:

PEOU → Attitude → Intention0.0742.97.003[0.026, 0.125]yes
PEOU → PU → Attitude → Intention0.0553.84< .001[0.029, 0.087]yes

The three routes reaching Intention from PEOU — PEOU→PU→Intention (0.167), PEOU→Attitude→Intention (0.074), and PEOU→PU→Attitude→Intention (0.055) — sum to 0.296, matching (up to ordinary bootstrap resampling variation) the 0.293 total Indirect effect already shown for PEOU → Intention back in §4. Same underlying arithmetic; here it's decomposed per route instead of summed, and every route gets tested for significance on its own.

All five routes are significant here — is that always expected? No — with a weaker or more indirect chain, it's common for the aggregate (Total & Indirect Effects) route to be significant while one of its longer specific routes isn't, or vice versa. That's exactly the kind of nuance this table is for.

6. Moderator constructs (interaction terms)

A moderator changes the strength of a relationship between two other constructs, rather than sitting on a causal chain like a mediator. UEH-WebSEM tests moderation with the standard two-stage approach (Henseler & Chin, 2010; Henseler & Fassott, 2010):

  1. Stage 1 — the base model (without the interaction) is estimated to obtain standardized construct scores.
  2. Stage 2 — an interaction term is formed as the standardized product of the two moderating constructs' Stage-1 scores, then the structural model is re-estimated with this term included as a predictor.

The same two-stage logic is applied for both PLS-SEM (composite scores) and CB-SEM (factor scores), so you can test moderation with either estimator.

Creating an interaction term in the builder

  1. Add at least two ordinary constructs first (an interaction always multiplies two existing, non-interaction constructs).
  2. Click “+ Construct”, enter a name, and set Measurement type to “Interaction / moderation term (A × B)”.
  3. Pick the two source constructs (e.g. “Perceived Usefulness” and “Attitude”).
  4. Draw a structural path from the new interaction node to the construct being moderated (e.g. → Behavioral Intention).
Validation rule Both source constructs must already have their own direct path to whatever the interaction term predicts. This mirrors standard moderation practice: without both main-effect paths present, the interaction term could silently absorb variance that actually belongs to a main effect. If a source is missing its direct path, the app rejects the model with a clear message naming the missing path — add it and re-run.

An interaction term is always exogenous (it cannot itself be the target of another path) and has no indicators of its own — on the canvas it is drawn with a dashed amber border to distinguish it from ordinary constructs.

Worked example, with real numbers from the TAM sample

Adding PU × Attitude → Behavioral Intention to the sample model (both PU and Attitude already have direct paths to Intention, so the model validates) gives:

Methodβ / Bt or zpSignificant (95%)
PLS-SEM (bootstrap, n = 2,000)−0.0902.05.041yes
CB-SEM (Maximum Likelihood)−0.052−1.52.129no

The negative sign means the joint influence of Perceived Usefulness and Attitude on Intention is slightly weaker when both are high — a mild ceiling effect. Note the two estimators disagree on significance here: PLS-SEM's composite-score approach and CB-SEM's factor-score approach handle interaction terms differently and can diverge, especially for small effects — a legitimate reason to report both when they're available, and not to treat either estimator's p-value as automatically definitive.

Moderation f² uses different thresholds

The interaction path above has f² = 0.013 in the PLS-SEM run. Effect-size labels for structural paths normally use Cohen's thresholds (small ≥ 0.02, medium ≥ 0.15, large ≥ 0.35) — by that scale, 0.013 would look negligible. But interaction effects are inherently harder to detect than main effects, so the literature (Kenny, 2018; Aguinis, Beaty, Boik & Pierce, 2005) recommends a much smaller scale specifically for moderation:

f² rangeModeration labelMain-effect label (for comparison)
< 0.005NegligibleNegligible
0.005 – 0.01SmallNegligible
0.01 – 0.025MediumNegligible / Small
≥ 0.025LargeSmall

UEH-WebSEM applies the moderation scale automatically to any path whose source is an interaction term (marked with a Moderation badge in the path table and export), so the reported f² = 0.013 for PU × Attitude → Intention is correctly labeled “Medium”, not “Negligible”.

Why Q² is skipped for models with a moderator Blindfolding (used to compute Q²) systematically omits and re-predicts raw indicator values, but an interaction term has no indicators of its own — it is a derived product of two other constructs' scores. Because of this, Q² is automatically skipped (with an explanatory note) for any model containing an interaction term; every other output (path coefficients, R², f², bootstrapping) is unaffected.

7. Index of Moderated Mediation (Hayes, 2015)

A mediator explains why or how X affects Y; a moderator explains when or for whom a relationship is stronger or weaker. Moderated mediation combines both questions: does the strength of an indirect effect itself depend on a moderator? UEH-WebSEM detects this automatically whenever a model contains a mediated route (X → M → Y) in which exactly one edge is the target of an interaction term, and reports Hayes' (2015) Index of Moderated Mediation — the slope of the indirect effect with respect to the moderator, i.e. how much the indirect effect changes per one-unit increase in the moderator.

This is scoped to routes with exactly one moderated edge. If both the a-path and the b-path of a route are moderated at once, the indirect effect becomes a bilinear (not linear) function of the two moderators, and Hayes doesn't define a single scalar index for that case — Hayes' own PROCESS macro handles it the same way, via conditional indirect effects evaluated at chosen moderator values instead of one index.

Worked example

Using Hayes' own notation — X (predictor), W (moderator), M (mediator), Y (outcome) — a small model with paths X → M, W → M, X × W → M (an interaction moderating the a-path), and M → Y gives:

Pathβp
X → M0.247< .001
W → M0.125.003
X × W → M0.170< .001
M → Y0.342< .001

The route W → M → Y is a mediated path whose first (a) edge, W → M, is itself moderated by X. PLS-SEM (bootstrap, n = 2,000) reports:

RouteModeratorIndextp95% CISignificant
X × W → M → YX0.0583.00.003[0.022, 0.099]yes

CB-SEM (Maximum Likelihood) reports the same index as a point estimate only: 0.056 — no separate significance test for this specific index is available under CB-SEM yet.

Reading the index 0.058 means: for every one-unit increase in X, the indirect effect of W on Y (via M) grows by 0.058. Because its 95% confidence interval [0.022, 0.099] excludes zero, the moderation of this mediated path is itself statistically significant — not just the individual a/b paths on their own, but X's moderating effect on the mediation chain as a whole.
Scope Only routes with exactly one moderated edge are reported, as explained above. For a model with both-stage moderation, read the Path Coefficients and Simple Slopes outputs directly at chosen moderator values instead.

9. PLSpredict — Out-of-Sample Predictive Validity

R² tells you how well the model fits the data you have, but not whether it would predict well for new respondents — those are genuinely different questions. PLSpredict (Shmueli, Ringle & Sarstedt, 2016) answers the second one via k-fold cross-validation (default k = 10):

  1. Split the data into 10 folds; hold out one fold as the test set and train the model on the remaining nine.
  2. Use the training fold's weights/coefficients to predict the endogenous indicators on the held-out (never-seen) test fold.
  3. Compare PLS's prediction error against a simple linear regression (LM) benchmark — an OLS regression of each indicator directly on the raw indicators of its predictor constructs, bypassing the composite score entirely.

Click "🔮 PLSpredict" on the results page to run it. On the TAM sample data (base model, no interaction term):

PU3Perceived Usefulness1.1460.9311.1430.925LM wins
ATT1Attitude1.1150.8921.0850.871LM wins
ATT2Attitude1.1100.8991.0880.884LM wins

PLS wins only 2 of 9 indicators ⇒ low predictive power, per Shmueli et al.'s rule of thumb (PLS wins all = high; wins most = medium; otherwise = low).

Why does LM usually win, and should that worry you? It isn't a sign the model is wrong. PLS compresses a construct's three indicators into one composite score and predicts through that composite, while LM regresses directly on all three raw indicators (more degrees of freedom). For an endogenous construct further from the root (like Behavioral Intention, reached through two mediating constructs), the compression error compounds, so LM tends to win more decisively. This is exactly what PLSpredict is designed to catch: cases where composite compression buys you no real predictive advantage over regressing on the raw items, even though in-sample R² still looks respectable.
Limitation PLSpredict doesn't yet support models containing an interaction (moderator) construct — the app returns a clear error if you try to run it on one.

10. IPMA — Importance-Performance Map

IPMA (Importance-Performance Map Analysis; Ringle & Sarstedt, 2016) answers a practical question: "which construct is most worth improving first?" For a target construct you choose, every one of its antecedent constructs is plotted on two axes:

  • Importance (x-axis) — the standardized total effect on the target construct, the exact same number already shown in the Total & Indirect Effects table (section 4).
  • Performance (y-axis) — the construct's average standing, rescaling each indicator to a 0–100 scale using that indicator's observed min/max in the data, then combining them with the same outer weights used to build the composite score.

Click "🎯 IPMA", choose Behavioral Intention as the target; on the TAM sample data:

ConstructImportancePerformance (0–100)
Perceived Ease of Use0.29651.2
Perceived Usefulness0.48149.4
Attitude0.35849.0

The chart draws two dotted lines at the mean Importance and mean Performance of the constructs currently shown, dividing the plane into 4 zones. Here, Perceived Usefulness has the highest importance (0.481) but the lowest performance (49.4) of the three — landing in the "important but underperforming" zone, making it the top candidate to prioritize if the goal is raising Behavioral Intention.

Why doesn't performance match the original response scale? Because the 0–100 scale is rescaled from the observed min/max in this particular dataset, not a fixed theoretical scale (e.g. a 1–7 Likert range). That means performance is only meaningful as a relative comparison across constructs within the same run — don't compare it directly across two different datasets.

11. Sample Size Sensitivity

The question "how large a sample is enough?" is normally answered with a power analysis before collecting data. Sample Size Sensitivity approaches it from the other direction, after the data already exists: it re-runs the model repeatedly on progressively smaller random subsamples, to see at what point the main results (R², path coefficients) start swinging around noticeably.

Click "📉 Sample Size Sensitivity", enter N (how many more observations to drop at each step); the results page opens in a new tab. With N = 20 on the TAM sample (original n = 250, running down to about 20 observations):

The results page plots this full trajectory on a chart, with a backing data table and distinct markers for any sample size where the model failed to converge.

Optional: significance (p-value) trajectory

CB-SEM's Maximum Likelihood fit already gives a p-value for every path at every step — free, and shown automatically. PLS-SEM has no closed-form significance test, so its p-value trajectory is opt-in: it needs an extra bootstrap run at every single step, so enable "Test statistical significance" in the modal and choose a resample count if you want it. At n = 30, the same PEOU → Attitude path — significant at every larger sample size tested here — is no longer statistically significant (p = .332): with so few observations left, the bootstrap standard error grows too large to distinguish this coefficient from zero, even though its point estimate is still a similar magnitude. This kind of instability is exactly what the p-value chart is designed to surface, alongside the R² chart.

Not a formal power analysis This is an empirical exploration tool ("how much is enough, based on this actual dataset"), not a substitute for a proper a-priori power analysis run before data collection to determine the minimum required sample size — see §12, Monte Carlo Power Analysis, for that.

12. Monte Carlo Power Analysis

Sample Size Sensitivity (§11) works backwards from data you already have. Power Analysis works forwards, before data collection: given a hypothesized population model (expected path coefficients and average indicator loadings) and a candidate sample size, what's the probability of correctly detecting each effect as statistically significant? No PLS-SEM software has a closed-form formula for this — PLS has no maximum-likelihood standard error to plug into one — so UEH-WebSEM answers it the only rigorous way available: Monte Carlo simulation.

For each candidate sample size n, repeated many times (n_mc replicates):

  1. Generate a synthetic dataset of size n from your declared population path coefficients and average loadings (reflective indicators only).
  2. Fit the real estimator — PLS-SEM or CB-SEM — on that synthetic data, exactly as it would fit real data.
  3. Test each path for significance: PLS-SEM via an inner bootstrap; CB-SEM via its analytic Wald test, no bootstrap needed.

Power at that n = the fraction of replicates where a given path came out significant (p < .05).

Scope Reflective (Mode A) constructs only — no formative (Mode B) and no interaction/moderation (Mode I) constructs. Both need a materially different synthetic-data-generating process that isn't implemented yet; the button is disabled with an explanation if your current model contains either.

Worked example

Declaring the TAM sample's own observed path coefficients (PEOU→PU = 0.462, PEOU→Attitude = 0.206, PU→Attitude = 0.331, PU→Intention = 0.354, Attitude→Intention = 0.359) and an average loading of 0.86 for every construct, at n = 100 / 150 / 200:

PathDeclared βPower @ n=100Power @ n=150Power @ n=200
PEOU → PU0.4621.0001.0001.000
PEOU → Attitude0.2060.5670.6000.800
PU → Attitude0.3310.9330.9671.000
PU → Intention0.3541.0001.0001.000
Attitude → Intention0.3590.9330.9671.000

The weakest declared path (PEOU → Attitude, β = 0.206) is exactly the one with visibly lower power at every sample size — only 57% at n = 100, still just 80% at n = 200 — while every stronger path is already at or near 100% power by n = 100. This is the practical value of power analysis: it tells you which specific relationships in your model actually need a bigger sample, rather than treating "n" as one number for the whole model.

CB-SEM is much cheaper to simulate CB-SEM's Maximum Likelihood fit gives every path's significance test analytically, with no inner bootstrap loop — roughly 20× cheaper per replicate than PLS-SEM. The CB-SEM button therefore defaults to far more Monte Carlo replicates (100 vs. PLS-SEM's 30) for the same time budget, giving smoother power estimates.
This can take a while A full run can range from several seconds to several minutes depending on the number of sample-size points, replicates, and (for PLS-SEM) inner bootstrap resamples you choose — the configuration modal shows a live time estimate as you adjust these, and the results tab shows a live countdown once the run starts.

13. Machine Learning Comparison

SEM path coefficients come from a confirmatory, theory-specified model. Machine Learning Comparison offers an independent, purely data-driven cross-check: for every endogenous construct, its direct predecessor constructs — the same predictor set the structural model itself uses — are fed as input features to several ML algorithms (Linear Regression, Logistic Regression, Decision Tree, Random Forest, SVM, Gradient Boosting/GBM, XGBoost, LightGBM, CatBoost), each evaluated by k-fold cross-validation, and the resulting feature importance is compared side by side against the SEM path coefficient for that same predictor → target edge.

The one importance measure used for that side-by-side comparison is permutation importance, computed identically for every algorithm regardless of type (linear coefficient, tree split, or SVM margin) — the only fair common yardstick across such different models. Each algorithm's own detail section additionally shows its "native" importance (regression coefficient, or feature_importances_ for tree/boosting models) alongside permutation importance.

Why does Logistic Regression report Accuracy/AUC instead of R²? Every SEM construct score is continuous, but Logistic Regression is a classifier. To include it, each target is split at its training fold's median into "High"/"Low" groups, computed separately per k-fold split to avoid leaking test-fold information — Logistic Regression then predicts which group an observation falls into. Since the task changes from regression to classification, so does the metric: Accuracy and AUC instead of R²/RMSE.

Worked example

Running four algorithms — Linear Regression, Logistic Regression, Random Forest, XGBoost — with k = 5 against Attitude (predicted from Perceived Ease of Use and Perceived Usefulness, exactly as in the structural model) on the TAM sample:

With only 250 observations and 2 predictors, these more flexible algorithms overfit their training folds and generalize poorly, while the much simpler Linear Regression still manages a modest positive R². This is itself useful information: it's a sign the true relationship here is close to linear, and a more complex model buys nothing over a simple one for this particular construct.

Inputs are construct scores, not raw survey items — so this "feature importance" lives at the same level as the SEM path coefficients, not at the level of individual questionnaire items. Agreement between the two approaches strengthens confidence in a finding; disagreement is a prompt for further scrutiny, not proof the SEM model is wrong — the Machine Learning side only optimizes predictive accuracy, with no hypothesis testing, so this isn't a statistical test that replaces SEM.

Every run also includes a Computation Transparency section showing the actual server-side source code for the k-fold/permutation-importance engine and for exactly the algorithms you selected, and both the merged comparison table and the full per-algorithm results can be exported to Excel/Word (§15).

Every practical fit index (CFI, TLI, RMSEA, SRMR, GFI, AGFI, NFI) clears its good-fit cutoff; only the χ² test itself is marginal, which is normal and expected — χ² almost always rejects large or non-normal samples even for a well-fitting model, which is exactly why the other indices exist.

15. Exporting reports

Both the Excel (.xlsx) and Word (.docx) exports on the main results page rebuild every table shown on screen — including Total & Indirect Effects, Specific Indirect Effects, Index of Moderated Mediation, and (when present) interaction-term rows and moderation-specific f² labels — directly from the analysis you just ran (no re-estimation, so exporting is instant). The Machine Learning Comparison page (§13) has its own separate Excel/Word export, rebuilding its comparison table and per-algorithm detail the same way. In both cases, the report's language always follows whichever language (VI/EN) is selected in the interface at export time, independent of the language used when you originally ran the analysis.

16. Troubleshooting

  • “Interaction term ‘X’ predicts ‘Y’, so ‘Z’ also needs a direct main-effect path to ‘Y’.” — Draw the missing direct path from the named source construct to the moderated target, then re-run. Both multiplicands of an interaction must carry their own main effect on the outcome.
  • “Need at least 2 other constructs to create an interaction term.” — Add and configure at least two ordinary (non-interaction) constructs before switching a construct's type to “Interaction / moderation term”.
  • Q² shows a skip message instead of a value — this is expected whenever the model contains an interaction term (see §6); it does not indicate an error.
  • CB-SEM rejects a formative construct — CB-SEM (Maximum Likelihood) only supports reflective (Mode A) measurement; switch the construct to PLS-SEM, or change its measurement type if that's substantively appropriate.
  • File upload rejected for too many rows — the tool caps uploads at 5,000 rows; aggregate or sample your dataset down first.
  • "PLSpredict doesn't yet support models with an interaction/moderation construct" — exactly as stated; this feature doesn't yet handle Interaction-type constructs. Temporarily remove the interaction term from the model (or check on a moderator-free version of it) if you want to run PLSpredict.
  • The IPMA button has no constructs to choose from — IPMA needs at least one endogenous construct (something with an incoming path); if your model is all-exogenous, draw a structural path first.
  • The "⚡ Power Analysis" button is disabled — Power Analysis (§12) only supports reflective (Mode A) models with no formative or interaction/moderation constructs; the synthetic-data generator doesn't yet handle either case. Hovering the disabled button shows the specific reason.
  • "This configuration would take too long" in Machine Learning Comparison — the number of endogenous targets × selected algorithms × k-fold count exceeded the time budget; select fewer algorithms (Random Forest and CatBoost are the two slowest) or reduce k, then try again.
  • An algorithm shows "(unavailable)" in the Machine Learning Comparison modal — that algorithm's library isn't installed on the server running this instance. Every algorithm ships pre-installed in the official desktop .exe, so this normally only appears on a custom self-hosted deployment.
